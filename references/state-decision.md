# 状态、信念与决策协议

## ROUND_TABLE_STATE 模板

以下是会话记录格式，不要求部署数据库，也不代表模型具有跨会话永久记忆。空项写未知或不适用。

```yaml
ROUND_TABLE_STATE:
  version: "3.1"
  topic_id: 本场唯一标识
  topic: 当前议题
  goal: 决策或求知目标
  topic_type: 事实/因果/预测/决策/价值/策略/混合
  time_horizon: 时间窗口
  mode: full # full / quick
  phase: diagnosis # diagnosis / qualification / debate / action / closed
  round: 0
  diagnosis:
    variables: []
    constraints: []
    reversibility: 未知
    highest_value_information: 未知
  participants: [] # 席位、姓名或匿名、来源、资格依据、适用范围
  sources: [] # S-ID、来源位置、日期和阅读范围
  evidence: [] # E-ID、内容、等级、来源、适用范围、同源分组、有效状态
  confirmed_facts: [] # 主张与证据ID；用户给定信息另注明核验状态
  rejected_assumptions: [] # 假设、否定原因、受影响主张
  standing_assumptions: [] # 尚未推翻，不等于已经证实
  disagreements: [] # 双方主张、事实/机制/价值分歧、解答所需证据
  beliefs: [] # H-ID、命题、窗口、当前判断、理由、依赖证据
  belief_updates: [] # 轮次、H-ID、prior、证据ID、方向、posterior、限制
  red_team: [] # 触发原因、最强挑战、核验结果与影响
  current_judgment: 未形成
  confidence: 未知 # 高 / 中 / 低 / 未知；说明依据
  key_unknowns: []
  decisions: [] # 方案、阈值及来源、适用条件、风险、复查触发
  next_step: 下一待解决问题或补证动作
  corrections: [] # 旧值、新值、原因、日期、失效结论
```

轮末展示增量，例如“新增 E3；H1 削弱；成交费用仍未知；下一步查净回款”。完整状态在恢复点提供，不每轮重复长表。

## 状态转换

- `可`：保留事实、人物、信念及轮次，沿 next_step 前进。
- `深入此节`：保持当前分歧，细化待验证前提。
- `引入`：先核验，更新 participants 和张力关系，不清空 beliefs。
- 纠正数据：旧证据标撤回或被替代，记录 corrections；重新评估所有直接依赖的主张、阈值与行动，不静默改写历史。
- `落地`：phase 设 action；生成条件方案，当前轮不再展开人物辩论。
- `止`：phase 设 closed；用已有材料收束，缺口照录。用户明确继续同题时从快照恢复，phase 回到 debate。
- 新议题：建立新 topic_id；仅复用明确仍适用的用户约束，不搬用旧结论。
- 上下文缺失：从用户提供或可见的快照恢复，缺少证据正文时标待重新读取。不得把快照的推演当作已核验来源。

## Belief Update 的实际操作

对命题明确事件、比较对象与期限，例如“未来三年持有资产的净结果优于今天出售后的备选方案”。明确净结果如何衡量，不能讨论中途偷换目标。

- 开局没有数据：prior 可为未知，不硬造 50%。
- 新证据增加/降低可信度：记录证据 ID、改变的前提、方向、posterior。
- 另一角色复述 E1：不是新证据，posterior 不因此提高。
- 同源报道 E2/E3：合并考量，不当三次独立确认。
- C 推演：只有带来新的有效推理才说明其影响，不当额外观察证据。
- E1 撤回：撤销基于它的信心增益，重新计算或改为未知。
- 只有可辩护的先验和似然时才量化；否则定性记录，不将选人评分当概率。
- 价值问题：记录优先级和代价，例如公平与效率如何取舍；不计算“公平正确的概率”。

## Decision Threshold 输出模板

```text
目标 / 期限 / 硬约束：
当前判断与信心：
关键变量 X（单位、观测方式、日期）：
阈值 A、B（来源或计算过程，A < B）：
  X < A       -> Plan A
  A <= X <= B -> Plan B
  X > B       -> Plan C
未知数据分支 -> 先补证 / 可撤销试验
各方案：收益、风险、执行成本、最坏后果
多变量冲突时：先满足硬约束，再比较目标结果
推荐的下一步：动作、由谁完成、期限、验收方式
切换/止损条件与复查时间：
```

符号模板不是通用买卖方向。根据目标决定区间对应行动，明确边界等号；如果阈值未确定就保留符号，不能伪装成计算完成。

### 资产选择示例（仅说明方法，不是市场建议）

用户给出报价 P 与贷款余额 L，最多可先写“初步净回款 = P - L - 税费 - 中介费 - 其他结清成本”。不能把 P-L 当确定可用资金，也不能把过去买价的亏损单独当继续持有理由。比较同一期限的持有净结果与出售后备选方案，纳入租金、维护、融资成本、流动性与用户资金需求。

税费、成交真实性、机会成本或未来购置时间未知时，下一步是核验这些数据；不填造 X/Y 成交阈值。用户催促落地时仍可给“先取得净回款明细、核实报价条件，再按资金缺口选择”的具体动作。

### 纯价值议题

输出不同价值前提分别支持什么立场、各自代价与无法调和之处。Decision Threshold 可标“不适用：未要求现实选择”；不强行生成价格区间或概率。
