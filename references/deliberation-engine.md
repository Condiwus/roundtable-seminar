# Deliberation Engine — v3.2.1 RC

让已有的重要候选接受压力：Dialectic 暴露真正分歧，Reasoning 判断哪些解释经得起证据和反例。

本文件只定义引擎内部工作；全局调度、状态、停止与输出规则属于 [Kernel](../SKILL.md)。默认 Light。没有真实分歧时直接返回，不制造正反双方。

## 1. 两种压力，动态切换

| Kernel 交来的瓶颈 | 当前操作 | 要改变的对象 |
|---|---|---|
| UNDERSTANDING | DIALECTIC | 定义、价值排序、隐藏前提 |
| DISCRIMINATION | REASONING | 竞争解释的相对可信度 |

不设置独立 Hybrid Mode，也不设置第二个 Mode Router。事实与价值混合只是问题描述，不是执行模式。

```text
DIALECTIC ←── Kernel 根据新瓶颈切换 ──→ REASONING
    │                                  │
    └──────── What changed? ────────────┘
                       │
                     Kernel
```

引擎发现瓶颈变化时，返回变化与新的 need，由 Kernel 选择下一操作；可以在同一次回答内完成切换，不必展示调度过程或等待用户确认。

- 澄清定义后出现可检验的现实命题：返回 DISCRIMINATION；若决定性事实缺失，返回 FACT。
- 比较解释时发现双方使用不同“成功”标准：返回 UNDERSTANDING；若只缺用户个人偏好，返回 PRIVATE INFORMATION。
- 所有解释都覆盖不了现象：返回 POSSIBILITY，而不是强选赢家。
- 现实测试或已有行动更有价值：立即交回 Kernel。切换不要求完整运行任一模式。

## 2. Light by Default

默认围绕一条核心分歧，提出最有力的挑战，形成当前判断和剩余未知。通常无需人物面板；一个论点与一个有力反例已经足够时，就到此为止。

只有轻量处理不能解决具体瓶颈，才增加相关席位、证据检查或更深入的交锋。“深挖”增加对同一前提的压力，不自动增加人物、篇幅或协议。

复杂讨论也没有 STANDARD / DEEP 的固定步骤清单。升级必须指出当前哪一处未解决；降级与退出遵循 Kernel。

## 3. Dialectic：找到真正分歧

只澄清会改变结论的词：它有哪些合理定义，边界在哪里，是否暗含价值排序；需要现实判断时再给可观察含义。已清楚的概念不重复定义。

例如“Gap 是浪费”可能意味着不赚钱、职业停滞、没有恢复，或偏离社会期待。这些命题不能混为一谈。

选择当前最深的一条裂缝。让最强立场直接回应对方的前提，例如：

- “即使收入降低是真的，也推不出这段时间没有价值。”
- “你把恢复视为目标，却还没有说明这段休息能否实现恢复。”

事实争议不能靠哲学立场解决；价值分歧也不能由多数人的选择自动裁决。无需为纯价值立场编造实验或假装存在客观胜者。

返回最小必要结果：真正分歧、导致分歧的前提、条件化理解；若出现现实命题，指出其中最影响判断的一条。无需固定输出 2–4 个立场。

## 4. Reasoning：比较解释

基本单位是 Claim，不是人物。同一人可以提出正确、错误和未知的不同命题。

围绕最可能改变排序的地方施压：某个机制能否解释现象，证据是否区分竞争解释，有什么反例，什么观察会改变判断。这些是可选检查角度，不是逐项流程。

“X 能解释现象”不等于“X 是主要原因”。例如低播放量同时可能由首帧、人群错配或样本波动产生；有内容质量问题的证据，也未必证明它主导了分发结果。

涉及预测、成功案例或因果外推时，检查适用总体、基础率与替代解释；缺可靠基础率就保留未知。证据分级、来源检验与查证停止条件统一见 [Evidence](protocols.md#evidence)。

区分证据不足、被削弱与在明确范围内被证伪。不能把“尚未找到支持”写成“已经推翻”。若支持不足但需要现实决策，给条件化判断，并把决定性未知交回 Kernel。

普通问题在 State 中保留主要 Claim 即可。只有满足 [Claim Ledger](protocols.md#claim-ledger) 的高阈值才建立台账；引擎不定义另一套字段、状态或触发器。

## 5. 事实与价值分开处理，再组合

Separate → Test → Recombine 是动态切换时的处理原则，不是第三种模式或必跑流程。

例如“应该买房，因为买房让我有安全感”包含：

- 价值：安全感对这个人有多重要？
- 现实命题：购买是否确实会改善其安全感？
- 选择：这种改善是否值得承担成本与流动性损失？

只有真正卡住的部分需要处理。用户已明确价值偏好时，不重新辩论其人生目标；关键财务数据缺失时，也不先召开思想圆桌。

示例切换：对 Gap 的“浪费”定义存在争议 → Dialectic 澄清；出现再就业风险命题 → Kernel 选择 Reasoning 或 Search；事实澄清后若仍有价值分歧，再返回 Dialectic。若行动已足够明确，直接结束思辨。

## 6. Cognitive Seats 与真人载体

需要多视角时，先选择哪种能力能改变当前讨论，再决定是否用真人表示。席位范围和人数由 Kernel 管理；匿名机制、实践、行为或价值视角通常足够。

真人入席检查：Relevance、Evidence、Experience、Distinctiveness、Recency。知名度不能替代专业相关性；资料不足时用匿名角色。

真人观点建立在本人著作、论文、原始访谈、演讲、官方资料或可靠二手来源上。引用需有可核查出处；材料不支持的观点不能以真人口吻补齐。

若没有直接讨论过当前问题，只能依据其公开思想推演，明确标注 **【基于其已知立场推演】**，并说明推演所依据的立场。推演不写成引语，不伪造经历、研究或实际参与。此真实性规则也适用于 Brainstorm 偶尔采用真人载体的情况。

## 7. 动态发言与主持

席位首次出现时，简要说明它的核心主张、依据和脆弱前提即可。需要人物介绍时只交代与问题相关的身份及邀请理由。

主持人“理性之锚”根据上一条重要主张，选择最可能改变讨论的回应者，避免固定轮流。可使用 `〖陈述〗`、`〖质疑〗`、`〖反驳〗`、`〖补充〗`、`〖修正〗`、`〖综合〗`。

每次发言必须改变一个有意义的对象：前提、概念、机制、变量、证据或判断。重复发言删除；没有强反例就承认没有，不制造戏剧冲突。主持人管理推理结构，每次追一条最值得追的裂缝。

反迎合由 Kernel 统一规定。普通反例检验不等于正式 Red Team；正式协议的触发与攻击方式仅见 [Red Team](protocols.md#red-team)。

## 8. 收敛与交回

压缩已重复的解释，保留仍有竞争力的候选和改变结论的条件。退出不要求候选减少到指定数量，也不要求满足一张清单中的“多数条件”。理解已改善，或继续思辨不再是最高价值动作，就交回 Kernel。

交回的是状态变化，不是完整辩论记录：

```text
What changed：定义、主张或判断的变化
Current judgment：当前最可支持的理解 / 条件化判断
Key unknown：仍最影响判断的未知（如有）
Next need：建议 Kernel 处理的一个瓶颈（如有）
```

用户可见的轮次摘要由 Kernel 的自适应输出规则决定。Claim 状态、Belief Update、置信度和阈值等专项工具按 [Protocols](protocols.md) 触发，不在本文件复制规则。
