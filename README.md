# Roundtable Seminar · 圆桌研讨会 v3.1

以求真为目标的议题驱动圆桌技能：先确定问题需要哪些认知能力，再寻找并核验真实人物，通过有依据的交锋形成判断、行动条件与知识网络。

本分支为 **v3.1** 升级提案；通过 PR 合并前，`main` 保持 v3.0。

## v3.1 的变化

```text
Topic Diagnosis -> Cognitive Seats -> 搜索与 Participant Qualification
     -> Evidence Levels + 动态交锋 + Red Team
     -> Belief Update -> ASCII 框架 -> Round Table State
     -> Decision Threshold / 知识网络
```

- **议题诊断**：明确真正决策、时间尺度、3–7 个变量、隐藏假设与最高信息价值。
- **认知席位**：按题选能力，再找真人；四维与人物库保留为参考，不再固定分配。
- **真人资格**：按相关性、证据、经验、差异、时效评分；材料不足时明确使用匿名认知角色。
- **证据等级**：A 一手、B 高质量二手、C 推演、D 假设；人物原话与模拟延伸分开。
- **红队**：三人以上趋同及行动建议前检验集体可能出错之处。
- **信念更新**：记录初始判断、新证据与变化，避免重复证据和虚假概率。
- **决策阈值**：给出方案与切换条件，缺数据时保留待求阈值，不编造价格。
- **持续状态**：继续、深挖、引入、纠错均更新同一场记录，减少重复开场。

保留动态真人视角、六种行动标签、意外视角、ASCII 思考框架、逐轮控制、三轮快速模式、知识网络及 org 原文归档。所有代表均为基于公开材料的模拟，不是真人参与或新发表观点。

## 使用

将本分支的 `SKILL.md` 和整个 `references/` 一起放入目标工具支持的技能目录，文件夹命名为 `roundtable-seminar`。由目标工具加载技能后输入：

```text
圆桌：AI 时代还需要学习外语吗？
快速圆桌：我们该如何权衡公平与效率？
```

第一条按轮等待；快速模式自动三轮。也可使用 `快速 [议题]` 或 `快 [议题]`。

- `可`：推进下一问题。
- `深挖` / `深入此节`：留在当前争议。
- `引入 [人名/角色]`：核验后加入或替换。
- `落地` / `该怎么做`：产出条件方案与具体步骤。
- `止`：结束并生成知识网络，即使信息不全也会收束并标明缺口。

不具备联网或可读人物资料时，会说明核验限制并使用标明构造性质的匿名席位。无文件能力时在对话中交付，不声称归档。状态默认只在当前上下文中维护；跨会话续接需提供快照和必要材料。

## 从 v3.0 迁移

整体替换技能文件及 references，重新加载技能。元数据中的原 `category/version/tags/trigger` 移至标准 `metadata` 下；自定义部署若读取这些字段，需要更新读取位置。正文使用任务相关参考文件按需加载，独立服务不能只摘主持人段落。

旧人物库的未核验 MBTI 和示例台词不再作为事实载入。org 归档沿用完整原文要求，目录遵从用户配置和当前环境，未配置时使用允许的工作区交付目录。v3.0 的历史仍可通过 Git 历史查看。

## 检查范围

这是指令与文档仓库，无应用构建或线上服务变更。[验收场景](references/validation-scenarios.md) 是行为回归素材，不等于已运行的自动化测试；结构校验也不能证明所有模型都会稳定遵守协议。
